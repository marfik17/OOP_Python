# Заключительный проект

## Тема
**HTTP-клиент и сервер с графическим интерфейсом на Python**

## 1. Цель работы
Разработать настольное приложение, позволяющее вручную отправлять HTTP-запросы и запускать локальный HTTP-сервер с графическим интерфейсом. В ходе работы изучаются HTTP/1.1, сокеты, обработка URL, сериализация сообщений, многопоточность и модульное тестирование.

## 2. Задачи
1. Реализовать разбор и проверку HTTP/HTTPS URL.
2. Реализовать формирование GET/POST-запросов и разбор HTTP-ответов.
3. Реализовать транспорт на основе TCP-сокетов и поддержку TLS-клиента.
4. Создать сервер с несколькими маршрутами и корректными кодами ответа.
5. Добавить GUI с вкладками клиента и сервера.
6. Выполнять сетевые операции в фоновых потоках и передавать результаты в GUI через очередь.
7. Подготовить unit- и integration-тесты.

## 3. Использованные средства
Использован Python 3.10+ и стандартные модули `tkinter`, `socket`, `ssl`, `threading`, `queue`, `urllib.parse`, `json`, `logging`, `unittest` и `dataclasses`. Сторонние HTTP-фреймворки и библиотеки запросов не используются.

## 4. Архитектура программы
- **App** — построение окон и вкладок, сбор пользовательского ввода, запуск фоновых задач и обновление интерфейса.
- **URLParser** — проверка URL и выделение схемы, хоста, порта и пути.
- **HTTPMessage** — сериализация HTTP-запросов/ответов, разбор ответов и декодирование chunked-тела.
- **HttpClient** — создание запроса, управление тайм-аутом и вызов транспортного уровня.
- **Transport** — абстрактный интерфейс сетевого обмена.
- **SocketTransport** — TCP-соединение, отправка данных, чтение ответа и TLS для HTTPS.
- **RequestHandler** — абстрактный интерфейс обработки запроса сервером.
- **BasicRouter** — реализация маршрутов приложения.
- **HttpServer** — управление слушающим сокетом и обработка клиентских соединений в потоках.

Взаимодействие классов показано в файле `class_diagram.puml`. Сетевые операции клиента выполняются в отдельном потоке. Сервер обрабатывает соединения независимо друг от друга. Обмен между рабочими потоками и графическим интерфейсом осуществляется через `queue.Queue`; очередь проверяется методом `root.after`, чтобы не обращаться к виджетам Tkinter из фоновых потоков.

## 5. Реализованные функции
### HTTP-клиент
Пользователь задаёт URL, метод GET или POST, дополнительные заголовки и тело запроса. Программа отображает код статуса, заголовки и тело ответа. Есть тайм-аут, проверка URL и заголовков, обработка ошибок соединения. HTTPS-клиент использует стандартный модуль `ssl`.

### HTTP-сервер
Сервер запускается на выбранном локальном порту, может быть остановлен, а журнал показывает время, метод, путь, статус и длительность обработки запроса. Размер заголовков и тела ограничен для защиты от чрезмерно больших запросов.

| Метод и путь | Результат |
|---|---|
| `GET /` | HTML-страница приветствия, 200 |
| `POST /echo` | Возвращает тело запроса, 200 |
| `GET /time` | Текущее время в JSON, 200 |
| `GET /headers` | Заголовки запроса в JSON, 200 |
| `GET /status/{code}` | Демонстрационный HTTP-статус |
| Неизвестный путь | `404 Not Found` |
| Некорректный запрос | `400 Bad Request` |

## 6. Проверка и тестирование
Автоматические проверки запускаются командой:

```powershell
python -m unittest discover -s tests -v
```

Тесты охватывают:
- URL: стандартные и пользовательские порты, HTTPS, путь и query-параметры, пустой и некорректный URL;
- HTTP-сообщения: сериализацию запроса/ответа, разбор статуса и заголовков, Content-Length, ошибочные сообщения и chunked-тело;
- маршруты: главную страницу, `/echo`, `/time`, `/headers`, `/status/418` и 404;
- интеграцию: реальные TCP-соединения клиента с сервером для GET, POST и нескольких маршрутов.

Тесты предназначены для повторного запуска на компьютере, где будет демонстрироваться проект. Перед сдачей необходимо запустить указанную команду и сохранить скриншот успешного результата. Текущий набор тестов подтверждает перечисленные сценарии, но не является исчерпывающей проверкой всех возможных HTTP-реализаций.

## 7. Инструкция по демонстрации
1. В терминале из папки проекта выполнить `python -m src.main`.
2. На вкладке сервера запустить сервер на порту 8080.
3. На вкладке клиента отправить `GET http://127.0.0.1:8080/`.
4. Выполнить `POST http://127.0.0.1:8080/echo` с телом `hello`.
5. Проверить `/time`, `/headers`, `/status/418` и неизвестный путь.
6. Отдельно выполнить тесты командой `python -m unittest discover -s tests -v`.

## 8. Скриншоты для отчёта
Добавить реальные скриншоты, сделанные при запуске приложения:
1. вкладка клиента с успешным GET;
2. POST `/echo` и возвращённое тело;
3. вкладка сервера с журналом запросов;
4. ответы `/status/418` и неизвестного пути;
5. консоль с успешным запуском тестов.

Скриншоты намеренно оставлены для добавления автором: они должны показывать фактическую работу программы на целевом компьютере, а не иллюстрации-заглушки.

## 9. Заключение
В рамках проекта создано учебное приложение с графическим HTTP-клиентом и локальным сервером. Реализованы проверка URL, формирование HTTP-запросов, разбор ответов, маршрутизация, обработка GET/POST, TLS на стороне клиента, многопоточность и автоматические тесты. Проект демонстрирует основные принципы сетевого взаимодействия и объектно-ориентированной организации кода.
