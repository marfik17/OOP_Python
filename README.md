# Отчет по практическим работам: Объектно-ориентированное программирование (ООП)

## 1. Название и описание задачи
Проект представляет собой комплекс лабораторных работ (Задачи 1–9), направленных на поэтапное изучение и применение ключевых концепций объектно-ориентированного программирования на языке Python. 

В рамках данного курса решены следующие задачи:
* **Задачи 1–2:** Моделирование объектов реального мира (класс `Cat`), создание экземпляров и простейшее взаимодействие через методы.
* **Задача 3:** Защита внутренней логики системы (класс `Car`) от неправильного использования пользователем. Реализация безопасного вождения только после прогрева двигателя.
* **Задача 4:** Управление внутренним состоянием объекта и масштабированием (класс `Graph`).
* **Задачи 5–6:** Создание иерархии классов для устранения дублирования кода по принципу **DRY** (базовый класс `Figure` и наследники `Line`, `Rect`, `Ellipse`).
* **Задачи 7–8:** Демонстрация гибкости кода с помощью полиморфизма — добавление новых фигур (`Triangle`) без изменения старой логики обработки списков.
* **Задача 9:** Создание полноценной мини-системы графического редактора со скрытыми координатами и полиморфным расчетом суммарной площади всех фигур.

## 2. Архитектура проекта
Программа наглядно демонстрирует применение трех основных принципов («китов») ООП:

### 1. Инкапсуляция
* **Защита состояний:** В классе `Car` переменная `_engine_temperature` скрыта от прямого изменения извне. Пользователь не может «сломать» логику машины вручную — он обязан взаимодействовать с ней только через публичные безопасные методы `start_engine()` и `drive()`.
* **Скрытие данных:** В классах `Graph` и `Figure` координаты (`_x`, `_y`, `_scale`, `_coords`) защищены нижним подчеркиванием. Чтение и запись выполняются строго через регламентированные методы `get_coords()` и `set_coords()`.

### 2. Наследование (Принцип DRY — Don't Repeat Yourself)
* Спроектирован мощный родительский класс `Figure`, который берет на себя хранение базовых свойств любой геометрической фигуры: кортеж координат (`coords`), толщину обводки (`width`) и цвет (`color`).
* Дочерние классы (`Line`, `Rect`, `Ellipse`, `Triangle`, `Circle`, `Square`) используют вызов `super().__init__(...)`, чтобы мгновенно перенять эти параметры от родителя. Программисту не нужно заново переписывать переменные цвета или координат в каждом новом классе — они описываются один раз.

### 3. Полиморфизм
* Различные классы имеют методы с одинаковыми именами (`draw()` и `calculate_area()`), но с совершенно разной внутренней логикой.
* Цикл обработки объектов не знает и не проверяет точный тип фигуры (круг это или треугольник). Он просто отправляет команду `.draw()`, а Python автоматически подставляет нужную реализацию для конкретного класса. Программа легко расширяется новыми типами фигур без переписывания старых циклов или добавления условий `if/else`.

## 3. Примеры использования
Ниже представлены ключевые фрагменты кода, показывающие работу с разработанными классами.

### Демонстрация инкапсуляции и защиты логики (Задача 3):
```python
my_car = Car()
my_car.drive()          # Ошибка! Двигатель не прогрет, ехать нельзя.
my_car.start_engine()   # Двигатель прогрет (температура = 90)
my_car.drive()          # Поехали!
```

### Демонстрация полиморфизма в графическом редакторе (Задачи 7-9):
```python
# Создаем список из абсолютно разных геометрических фигур
figures_list = [
    Line(coords=(0, 0, 10, 0), width=2, color="black", length=10.0),
    Circle(coords=(0, 0), radius=5.0),
    Square(coords=(2, 2), side=4.0),
    Triangle(coords=(0, 0, 3, 4, 6, 0), width=1, color="green")
]

# Один простой цикл для управления всеми фигурами
for shape in figures_list:
    shape.draw()  # Каждый объект сам знает, как себя нарисовать в консоли
```

В вашем репозитории файлы распределены по задачам следующим образом:
